# Architecture

## Decision

Dashboard authoring and storage use Grafana's App Platform V2 API. Kubernetes
delivery remains on Grafana Operator's stable `GrafanaManifest` CRD:

```text
GrafanaManifest (grafana.integreatly.org/v1beta1)
└── spec.template: Dashboard (dashboard.grafana.app/v2)
```

Both layers are JSON. The extensionless `generated/cluster/manifests/Kustomization`
is also JSON accepted by Kustomize.

## Boundaries

`profile` describes what a dashboard query needs: datasource plugin and variable
identity. Kubernetes namespace, instance selector and reconciliation period live
in `delivery`; putting them in `profile` made portable models cluster-aware.

`queries` returns strings and imports no Grafana package. `panels` translates
those strings to Dashboard V2 query groups and visualizations. `common` owns
dashboard defaults plus the otherwise error-prone split between `elements` and
`layout`. Dashboard packages only compose these APIs.

Registration is explicit. Each domain package exports `Dashboards()` and the
catalog aggregates them once. There are no mutable globals, `init()` ordering or
hidden imports.

## Artifact contract

Raw resources under `dashboards/` support review, API import and reuse outside
Kubernetes. Only entries with `Publish: true` are written there.

Deployable entries additionally set `Delivery`. They become inline
`GrafanaManifest` resources under `manifests/`, along with their folder and an
artifact-local Kustomization. Flux therefore pulls the OCI artifact once per
release; the operator does not pull that artifact once per board on every
resync.

The example board is intentionally not deployable. It exercises builders and
goldens without creating tutorial content in production.

## Invariants

- Metadata name is the dashboard UID: DNS-1123, kebab-case, at most 40 chars.
- Every panel has one stable element key and exactly one layout reference.
- Panel layout stays within 24 columns and never overlaps.
- Datasources are declared variables; queries may not embed instance UIDs.
- PromQL is accepted by both VictoriaMetrics and Prometheus parsers.
- Grafana variables occur only in label matcher values.
- Rate functions use `$__rate_interval`.
- Generated bytes are deterministic and capped at 512 KiB per raw resource.

The conformance suite reads rendered JSON rather than SDK structs. This makes an
SDK bump visible through golden diffs while keeping project rules tied to the
wire format Grafana receives.

## Upgrade procedure

1. Bump the Foundation SDK exact version and run `go mod tidy`.
2. Fix compile errors at the `profile`, `panels`, and `common` adapters first.
3. Run `make golden`; review every wire-format difference.
4. Run `make check` and `make dry-run` against a cluster with the target CRDs.
5. For operator changes, perform a disposable create → update → delete canary
   before promoting the OCI release.

Dashboard V2 and the SDK are public preview, so an apparently mechanical bump
is treated as an API migration rather than routine dependency maintenance.
